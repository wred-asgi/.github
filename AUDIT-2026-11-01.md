# Organization audit — 2026-11-01

Scope: all eight extensions, their composition contract, dependency ranges,
installed distributions, shared-service behavior, and operational guidance for
Wred 0.15. No core runtime changes were needed. Candidate versions and deployment
requirements are in [PRODUCTION.md](PRODUCTION.md).

## Repairs

- All extension dependency ranges now admit Wred 0.15; contract revision 1.1
  specifies query replacement decoding and raw-byte cache identity. A composed
  cache/validation/pagination regression covers those semantics.
- Cache now bounds entry bytes, retained memory bytes, version cardinality, fill
  locks, Redis connections and backend waits. Version loss rotates generations;
  expired Redis fill leases cannot overwrite a newer result. Request/response
  `no-cache` and `Vary: *` bypass storage. Cleanup failures preserve the original
  handler error/cancellation; backend failure never retries handler execution.
- Auth account routes enforce streaming/cached-body size limits before parsing or
  database work. Token and MFA input sizes and TTL configuration are checked.
  Shutdown attempts both owned backends on failure/cancellation and shields
  outstanding password work from shutdown cancellation.
- Pagination defaults to a bounded offset; cursor configuration, token size, and
  directly constructed pagination objects are validated.
- OpenAPI serves preloaded local assets; Swagger UI upgraded from 5.17.14 to
  5.34.1 with archive integrity verification, per-file digests, and a reproducible
  update script. Upstream license/notice files remain bundled.
- Raised affected dependency floors in auth, cache, and CORS. Audited both the new
  direct runtime floors and the complete resolved validation environment. Existing
  floors allowed affected Authlib, PyJWT, cryptography, PyMongo, orjson, and
  Starlette versions. Advisory applicability varies by API; this review did not
  establish an exploit against every extension that used those distributions.
- Every repository now invokes shared organization CI; the reusable workflow
  builds all distributions and requires Redis/PostgreSQL/MongoDB-backed tests.
  Weekly checks detect drift in independently released dependencies.

  1 skipped**. All eight wheels and sdists built; every sdist rebuilt to a wheel.
  Tests ran outside source checkouts; `pip check` passed.
- Clean Python 3.11.11 / Wred 0.15 with **all common runtime dependency floors**:
  **237 passed, 1 skipped**, plus clean dependency/advisory checks.
  [Exact minimum environment](evidence/dependencies-minimum-py311.txt).
- Python 3.11.11 / Wred 0.14 / Starlette 1.3.1 wheels: 234 passed, 2 skipped before
  those shutdown cases. The additional skip is the 0.15-only query contract.
- The intentional service-test skip is SQLite's single-writer concurrency case;
  equivalent PostgreSQL/MongoDB cases ran. Redis, PostgreSQL 18 and a MongoDB
  8.2.9 replica set on Linux 6.17 were real disposable services, not mocked stores.
- Cache/auth/pagination regressions were demonstrated against the pre-fix owner
  before repair; cache cleanup regressions also failed against the prior commit.
  The CORS test was corrected to require its `Vary` dimensions while allowing
  additional upstream dimensions, rather than asserting an exact header inventory.
- Resolved Python dependency scans and updated direct-floor scans reported no known
  vulnerabilities at the time of the run. This is advisory coverage, not a security
  proof. Bundled JavaScript and unpublished extension source need separate review.
- Two Authlib 1.x deprecation warnings remain (HTTPX adapter and JOSE API). Authlib
  is capped below 2; provider tests validate signatures/nonce/PKCE without live
  provider credentials. Inert lint checks and `git diff --check` passed.

## Load evidence

[Machine-readable results](evidence/load-2026-11-01.json) record configuration,
latencies and outcomes. All runs used the same development host; some checks ran
concurrently. These are correctness/overload samples, not maximum capacity claims.

| Exercise | Configuration | Observed result |
|---|---|---|
| Shared cache | 4 processes, 25 lanes/process, 10 keys, 10,000 calls before and after invalidation | 20,000 correct responses; 20 origin fills; no stale post-invalidation results |
| Shared moving quota | 4 processes, 25 lanes/process, 1,000 identities, quota 5 | Exactly 5,000 accepted and 5,000 denied out of 10,000 |
| PostgreSQL auth | 2 processes, 2 concurrent calls/process, 1,000 mixed operations | 900 successful authentications and 100 successful logins |
| MongoDB auth | Same normal configuration | 900 successful authentications and 100 successful logins |
| PostgreSQL auth overload | 4 concurrent calls/process; 2 password jobs/process | 900 successful authentications; 35 logins accepted, 65 rejected with controlled 503 |
| MongoDB auth overload | Same overload configuration | 900 successful authentications; 37 logins accepted, 63 rejected with controlled 503 |
| CORS HTTP | 2 workers, 50 concurrent clients, 10,000 allowed origins, 2,000 requests | No errors; both workers observed on routed requests |
| CORS preflight HTTP | Same setup, 2,000 preflights | No errors; preflights terminate before worker-identifying route headers |

Auth/cache/quota harnesses exclude HTTP, proxy, external provider, and email costs.
CORS includes localhost HTTP with load client and server on the same host. Run
sustained, isolated load and failure/recovery exercises before adopting an SLO.

## Release status and remaining operational gates

These are coordinated source release candidates, not a claim of registry
publication. New dependency floors and default limits require migration review.
Live OAuth tenant configuration, real email delivery, regional/cluster failover,
backup restoration, long-duration memory soak, and production workload capacity
remain deployment-specific gates. GitHub workflow files do not themselves enable
required branch checks or prove that a remote run completed successfully.

Remote CI setup exposed the documented MongoDB 8.x/host-kernel incompatibility.
The shared workflow uses the unaffected MongoDB 7.0 line and retains replica-set
transactions; see the [host compatibility notes](PRODUCTION.md#mongodb-host-compatibility).
